Ingestion / Watermark / Transaction model

Question this prototype answers Does the idempotent-upsert-plus-watermark design actually behave correctly across the cases that matter: a normal catch-up run, re-running when there's nothing new (must not duplicate anything), and a crash partway through a batch of several new games (must roll back completely — no half-saved data, no watermark pointing past unsaved rows)? This simulates one player's data flowing from "Riot's servers" into "our Postgres" — everything here is in-memory, nothing is a real API or database.
